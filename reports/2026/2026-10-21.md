## 🔥 1. Top 5 — Must Know

### 1. NEW — GitHub Package Firewall เปิด Public Preview (9.4/10)
**ประกาศ:** 20 ต.ค. · **Maturity:** Preview · **Recommendation:** Try (ผู้มีสิทธิ์) · **Effort:** 45–90 นาที

**เกิดอะไรขึ้น:** GitHub Enterprise Cloud เปิด Package Firewall ที่วางตัวกลางระหว่าง CI/CD runners หรือ Coding Agents กับ upstream package registry เพื่อตรวจ metadata และไฟล์ package ก่อนติดตั้ง มี cooldown policy, advisory checks, attestation downgrade checks และ exception workflow. **รองรับเฉพาะ npm**; Preview ฟรี แต่ GA จะคิดค่าใช้จ่ายตาม usage.

**ทำไมสำคัญ:** ลดความเสี่ยง malicious packages ที่รันระหว่าง `npm install` และขโมย credentials ใน CI/agent environments. เหมาะกับ Next.js, GitHub Actions, Node tooling; **ยังไม่รองรับ NuGet หรือ GitLab CI โดยอัตโนมัติ**.

**Who should care:** Next.js, npm, DevSecOps, AI Engineering, CI/CD.
**Primary:** https://github.blog/changelog/2026-10-20-github-package-firewall-in-public-preview/

### 2. NEW — Argo CD v3.5.6 แก้ปัญหา GitOps ที่มีผลจริง (9.0/10)
**Release:** 20 ต.ค. · **Maturity:** Production Ready · **Recommendation:** Try on Staging หากได้รับผลกระทบ · **Effort:** 30–90 นาที

**เกิดอะไรขึ้น:** แก้ gRPC SRV lookup, SSH repository fetch ผ่าน SOCKS5 proxy และ server-side diff ที่รายงาน fields ที่ถูก manager อื่นลบเป็น diff อย่างไม่ถูกต้อง.

**ทำไมสำคัญ:** ลดปัญหา repo connectivity และ false OutOfSync ใน Argo CD deployments. เป็น operational patch ไม่ใช่ major feature; ไม่จำเป็นต้องอัปเกรดทันทีหากไม่พบอาการ. ทดสอบ reconciliation/diff ก่อน production rollout.

**Who should care:** K3s, Kubernetes, Argo CD, Helm, GitOps.
**Primary:** https://github.com/argoproj/argo-cd/releases/tag/v3.5.6

### 3. NEW — GitHub Secret Scanning Audit Log เปลี่ยน 12 พ.ย. (8.7/10)
**ประกาศ:** 20 ต.ค. · **Effective:** 12 พ.ย. · **Maturity:** Production change scheduled · **Recommendation:** Try (audit integration) · **Effort:** 20–45 นาที

**เกิดอะไรขึ้น:** `business` ใน `secret_scanning_alert.*` และ `secret_scanning_push_protection.bypass` audit events จะเปลี่ยนจาก enterprise display name เป็น slug โดย `business_id` ยังเหมือนเดิม. เพิ่มการ revoke encoded GitHub tokens ในบาง private/internal repositories ที่เปิด scanning (preview).

**ทำไมสำคัญ:** SIEM, alert routing และ compliance scripts ที่ filter display name อาจหยุดทำงานหลัง 12 พ.ย. ควรเปลี่ยนมาอ้างอิง `business_id` หรือรองรับทั้งสองรูปแบบระหว่าง migration.

**Who should care:** DevSecOps, GitHub Enterprise, SIEM.
**Primary:** https://github.blog/changelog/2026-10-20-updates-to-github-secret-scanning/

### 4. NEW — Dependabot Alerts REST API เพิ่ม `version_requirement` (8.5/10)
**ประกาศ:** 20 ต.ค. · **Maturity:** Production Ready · **Recommendation:** Try · **Effort:** 20–40 นาที

**เกิดอะไรขึ้น:** REST alerts และ webhooks แสดง resolved version จาก lockfile หรือ version constraint จาก manifest/submission เพิ่มเติมจาก vulnerable range เดิม. ฟิลด์อาจเป็น `null`, truncated หรือไม่ครอบคลุมทุกเวอร์ชันในบาง alerts.

**ทำไมสำคัญ:** ช่วยทำ NuGet/npm vulnerability triage, security dashboards และ SBOM enrichment โดยไม่ต้อง parse lockfiles ทุกครั้ง.

**Who should care:** C#/.NET, NuGet, Next.js, Security Automation.
**Primary:** https://github.blog/changelog/2026-10-20-dependabot-alerts-rest-api-now-includes-dependency-versions/

### 5. NEW — GitHub Bulk Branch Protection → Rulesets (8.2/10)
**ประกาศ:** 20 ต.ค. · **Maturity:** Production Ready · **Recommendation:** Try on test repo · **Effort:** 20–45 นาที

**เกิดอะไรขึ้น:** Settings → Rulesets → Import branch protection rules แปลง rules ทั้ง repository ในครั้งเดียว พร้อม preview, enforcement status (Active/Evaluate/Disabled) และตัวเลือกเก็บหรือลบ rules เดิม.

**ทำไมสำคัญ:** ช่วยทำ policy governance แบบ layered rulesets, branch patterns และ granular bypass โดยลดงาน manual; ตรวจความเท่าเทียมของ policy ก่อนลบ classic protections.

**Who should care:** Platform Engineering, GitHub Admins, CI/CD.
**Primary:** https://github.blog/changelog/2026-10-20-bulk-migrate-branch-protections-to-rulesets-for-a-repository/
