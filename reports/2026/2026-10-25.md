### 🥇 1. BACKFILL — PHP2Shell: 2 Critical PHP Engine RCE Vulnerabilities
**วันที่ 21 ต.ค. | Maturity: Production Ready (patched builds) | Recommendation: Try (patch/audit) | Effort: 30–120 นาที + rollout**

**What happened:** PHP ออก Security Releases แก้ CVE-2026-109618 และ CVE-2026-109619 ซึ่งอาจเปิดทางให้ unauthenticated remote code execution ใน PHP ที่ประมวลผล Web Requests. เวอร์ชันที่แก้ไขแล้ว: **8.5.12 / 8.4.27 / 8.3.36 / 8.2.35** หรือ Distribution Packages ที่ Backport Patch แล้ว

**Why it matters:** แก้ที่ Application Code, Composer หรือ Framework ไม่เพียงพอ เพราะช่องโหว่อยู่ใน PHP Engine. ต้องตรวจทั้ง Host, PHP-FPM, Apache/mod_php และ Docker Images; หากมีการเปิดบริการสู่ Internet ให้ตรวจ Logs/Indicators of Compromise ตาม Advisory ด้วย

**Who should care:** Platform/DevOps, PHP Teams, ทีมดูแล Containers และ CI Security. **ไม่ใช่ช่องโหว่ของ .NET หรือ GitLab Server โดยตรง** และไม่ควรสรุปว่า Next.js/C# ได้รับผลกระทบหากไม่มี PHP Runtime

**Primary:** [PHP 8.5.12 announcement](https://news-web.php.net/php.announce/513) · [PHP security advisory](https://www.php.net/archive/2026.php#2026-10-21-5) · [GitLab remediation/inventory guide](https://about.gitlab.com/blog/gitlab-helps-remediate-critical-php-flaws/)

### 🥈 2. BACKFILL — GitLab Business Logic Security Analyzer ตรวจ API Authorization ที่ SAST มักพลาด
**วันที่ 20 ต.ค. | Maturity: Preview (limited early access) | Recommendation: Watch / Try if eligible | Effort: 1–3 ชั่วโมง + onboarding**

**What happened:** GitLab Duo Agent Platform เปิด Early Access ให้ Business Logic Security Analyzer บน GitLab.com สำหรับ GitLab Ultimate บางกลุ่ม. ระบบอ่าน Repository ทั้งระบบและพยายามตรวจ **BOLA/IDOR, missing authorization, mass assignment** แล้วส่ง Findings เข้า Vulnerability Report/Merge Request Security Widget

**Why it matters:** ใน ASP.NET Core Web API การมี `[Authorize]` ไม่ได้แปลว่าตรวจ Owner/Tenant ของ Record ครบทุก Endpoint; SAST แบบ Pattern-based มักมองไม่เห็น Business Intent. การตรวจด้วย Agent เป็นอีกชั้น ไม่แทน Integration Tests, Code Review และ Security Controls

**Who should care:** C#, ASP.NET Core, EF Core, API Security, GitLab CI. **ข้อจำกัด:** ยังไม่ GA; ใช้ GitLab-managed Models และ GitLab Credits; ต้องประเมิน False Positives/Privacy ก่อนนำเข้ากระบวนการจริง

**Primary:** [GitLab official engineering announcement](https://about.gitlab.com/blog/gitlab-business-logic-security-analyzer/)

### 🥉 3. BACKFILL — GitLab AI Governance Dashboard (Beta) มองเห็นการทำงานของ Coding Agents
**วันที่ 20 ต.ค. | Maturity: Preview (beta) | Recommendation: Try if eligible | Effort: 45–90 นาที**

**What happened:** GitLab เพิ่ม Dashboard รวม Agent Sessions, Tool Calls, Models, Users และ Projects จาก Duo Agent Platform และ Agent ภายนอก เช่น Claude Code, Codex, Cursor. สามารถเก็บ Audit Events และตรวจสอบ Session ได้

**Why it matters:** ทีมที่ใช้หลาย Coding Agents จะติดตามว่าใครให้ Agent แก้ Repository ใดและใช้ Tool อะไรได้ดีขึ้น. สำหรับ GitLab Premium/Ultimate ต้องเปิด **Store AI audit events** เอง (ปิดเป็นค่าเริ่มต้น); GitLab CLI 1.122.0+ รองรับ `glab govern setup` / `glab govern doctor` บน macOS/Linux เพื่อจับ External Agent Sessions

**Who should care:** GitLab Administrators, DevSecOps, AI Platform, Coding Agent Teams. **ข้อจำกัด:** ต้องตรวจ Edition/Environment/Permissions; การ Capture อาจมี Sensitive Session Data

**Primary:** [GitLab AI Governance Dashboard](https://about.gitlab.com/blog/ai-governance-dashboard/)

### 4. NEW — GitHub Public Monitoring เปิด Preview สำหรับ Data Residency
**วันที่ 22 ต.ค. | Maturity: Preview | Recommendation: Watch / Try if eligible | Effort: 30–60 นาที**

**What happened:** GitHub Enterprise Cloud with Data Residency สามารถเปิด Public Monitoring เพื่อตรวจ Credentials ที่หลุดไปยัง Public Commits ได้ โดยผูกเหตุการณ์กับองค์กรผ่าน **Verified Domains** และส่ง Alert ภายใน Data Residency Boundary

**Why it matters:** เพิ่มการตรวจ Secret Leakage นอก Private Repositories โดยไม่ต้องแชร์ Membership Roster ข้าม Boundary. เป็นคนละ Milestone กับ Public Monitoring REST API/Triage/Webhooks ที่รายงานวันที่ 24 ต.ค. — วันนี้รายงานเฉพาะ **Data Residency Availability**

**Who should care:** GitHub Enterprise, Security Operations, Compliance. ต้องมี GitHub Advanced Security หรือ GitHub Secret Protection License

**Primary:** [GitHub Changelog — Data Residency](https://github.blog/changelog/2026-10-22-public-monitoring-now-available-with-data-residency/)

### 5. NEW — GitHub แก้ปัญหา SCIM Deprovisioning ที่ลบ Enterprise Managed Users ผิด
**วันที่ 23 ต.ค. | Maturity: Production Ready (remediation) | Recommendation: Watch / Check | Effort: 15–30 นาที**

**What happened:** GitHub แจ้งว่าในช่วง **1–13 มิ.ย. 2026** ระบบ SCIM บางกรณีลบ Enterprise Managed User (EMU) Accounts แทนการ Suspend/Obfuscate กระทบราว **12,285 Accounts** (มี 76 Accounts ที่ยัง Active ตอนถูกลบ). GitHub ระบุว่าได้แก้ Code และ Restore Records ในเดือน ต.ค.

**Why it matters:** กระทบ Traceability ใน Issues, PRs และ Audit Logs. ตรวจ `user.delete` ใน Enterprise Audit Log ของช่วงเวลาดังกล่าวได้ แต่ GitHub ระบุว่า Enterprise Owners **ไม่ต้องดำเนินการแก้ไข** เพิ่ม

**Who should care:** GitHub Enterprise Admin, Identity/SCIM, Compliance. **ไม่เกี่ยวกับ GitLab Self-managed หรือ GitHub Personal Accounts โดยตรง**

**Primary:** [GitHub EMU deletions fix](https://github.blog/changelog/2026-10-23-emu-deletions-fix/)

## ☸️ 3. DevOps / Kubernetes Radar

ยังไม่พบ Kubernetes, K3s, Argo CD, Helm หรือ Docker Major Release ใหม่ที่ผ่านเกณฑ์ในช่วงสุดสัปดาห์นี้. เน้น Security Inventory: ตรวจว่ามี PHP-based Services/Sidecars/Build Containers ที่ยังใช้ Runtime ไม่ได้รับ Patch หรือไม่; เพิ่ม kube-bench เป็น Host Security Assessment (ไม่ใช่การสแกน YAML เหมือน kube-score)

สำหรับ K3s Cluster ให้ทดลอง stern แบบ Read-only:
```bash

```

## 🧰 Tool of the Day — stern

**Problem:** `kubectl logs` ต้องเลือก Pod/Container; เมื่อ ReplicaSet เปลี่ยนระหว่าง RollingUpdate Pod Name เปลี่ยนตาม ทำให้ดู Logs ต่อเนื่องลำบาก

**Solution:** [stern](https://github.com/stern/stern) Tail Logs จาก Pods หลายตัว, ตาม Resource Name/Regex และติดตาม Pods ใหม่อัตโนมัติ. ใช้งานบน Windows ได้ผ่าน WinGet หรือ Krew:
```powershell
winget install stern.stern
stern deployment/be-api -n bigo-prod --since 10m --tail 100
```
**Maturity:** Production Ready (Established OSS) | **Recommendation:** Try | **Effort:** 10–20 นาที. ต้องมี Kubernetes RBAC สำหรับ `pods/log`; ระวัง Logs มี PII/Secrets

## 🧪 Try This Today

**ทดลอง stern กับ Deployment `be-api` ใน K3s:** เปรียบเทียบกับ `kubectl logs -l app=be-api -n bigo-prod --tail=100`, ตรวจว่าการ Tail ข้าม Replicas อ่านง่ายขึ้นหรือไม่ โดยไม่ต้องแก้ Workloads. จากนั้นทำ API Security Checklist เพิ่มเติม: Record Ownership, Tenant Isolation, Mass Assignment และ Audit Trail — ตรงกับแนวทาง GitLab Business Logic Analyzer แม้ยังเข้า Early Access ไม่ได้
