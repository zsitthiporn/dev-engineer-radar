### 🥇 NEW — Gheist: GitHub Actions ถูกใช้ขโมย Secrets ผ่าน Stolen Tokens

**เกิดอะไรขึ้น:** Wiz Research เผยแพร่ผลสอบสวนวันที่ **25 ต.ค. 2026** เกี่ยวกับแคมเปญ Gheist ที่ติดตามตั้งแต่ 15 ก.ย. ผู้โจมตีใช้ GitHub tokens ที่ถูกขโมยสร้าง Branch รูปแบบ `ci-sync-*` และไฟล์ `.github/workflows/sync-check.yml` เพื่อพยายามนำ Secrets ออกผ่าน GitHub Actions Logs จากนั้นดึงและลบ Run อย่างรวดเร็ว. นักวิจัยพบ **มากกว่า 13,500 branches** ใน **มากกว่า 850 accounts**. การ Hold Runs ที่น่าสงสัยใน Public Repositories ป้องกันการรันที่ทีมตรวจพบ แต่ทีมพบการรันสำเร็จใน Private Repositories และ GitHub Enterprise environments.

**ทำไมสำคัญ:** GitHub Token ที่มีสิทธิ์เขียน Repository สามารถกลายเป็นทางเข้าถึง CI/CD Secrets; การตั้ง `permissions: {}` ของ `GITHUB_TOKEN` ไม่ได้จำกัดการอ่าน Secrets Context. การลบ Branch/Logs ไม่ทำให้ Credentials ที่หลุดกลับมาปลอดภัย. **Who:** GitHub Actions, DevSecOps, Platform/Cloud Security, ทีมที่ Mirror GitLab → GitHub. **Maturity:** Incident confirmed; defensive controls Production Ready. **Recommendation:** **Try** (audit immediately). **Effort:** 30–90 นาทีสำหรับ Triage แรก; Incident Response เพิ่มตามขอบเขต.

**ตรวจแบบปลอดภัย:** ค้นหา `ci-sync-*`, `sync-check.yml`, Commit `ci: sync config`, Audit Events/Deleted Runs และ OIDC Assumptions จาก Branch แปลก; ตรวจ PAT/App Token Permissions และ Environment Protection Rules. หากพบร่องรอยให้ Revoke Tokens, Rotate Secrets ที่เข้าถึงได้ และสอบสวน Self-hosted Runners. **ไม่ใช่ทุก GitHub Repository ถูกเจาะ** — ตรวจเฉพาะหลักฐานในองค์กรของตน.

**Primary:** [Wiz Research — Gheist](https://www.wiz.io/blog/gheist-attempted-scaled-abuse-of-stolen-github-tokens-stumbles) · [GitHub Actions secure use](https://docs.github.com/en/actions/reference/security/secure-use)

### 🥈 UPDATE — Azure Functions ชี้แจง Rollout ของ .NET OOB Security Patch

**อะไรเปลี่ยนจากรายงาน 26 ต.ค.:** Microsoft Azure App Service Team ออกสถานะ **26 ต.ค.** ว่า Patch สำหรับ **Linux Azure Functions** อยู่ระหว่าง Rollout ทั้ง Consumption, Dedicated, Elastic Premium และ Flex Consumption; **Windows Functions** รอ App Service Windows Runtime Rollout ซึ่งยังไม่เสร็จ; **Azure Static Web Apps managed functions** กำลัง Rollout ตาม Linux Functions. จึง **ห้ามสมมติว่า Managed Platform ได้ Patch ทุก Instance แล้ว**. ข่าวนี้ต่างจากการประกาศ .NET OOB วันที่ 25 ต.ค. ที่รายงานไปแล้ว.

**ทำไมสำคัญ:** Platform-managed, self-contained และ custom containers มีความรับผิดชอบการ Patch ต่างกัน. **Who:** .NET Azure Functions, ASP.NET Core, DevOps. **Maturity:** Production rollout in progress. **Recommendation:** **Try** (verify running runtime and deployment model). **Effort:** 30–90 นาที.
