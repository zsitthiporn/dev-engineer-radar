### 1) NEW — GitHub Actions workflow dependency lockfiles GA (28 ต.ค.)
**What happened:** GitHub Actions รองรับไฟล์ .github/workflows/actions.lock แบบ GA แล้วบน Free, Team และ Enterprise Cloud สามารถล็อก commit SHA ของ direct/transitive actions แม้ workflow ยังคงอ่านง่ายด้วย tags; Dependabot อัปเดต lockfile พร้อม dependency PR และผู้ดูแลสามารถบังคับ Require lockfile policy ได้

**Why it matters:** ลดความเสี่ยง action tag ถูกย้ายหรือ dependency เปลี่ยนโดยไม่ตั้งใจใน CI/CD; lockfile ไม่ได้พิสูจน์ว่า dependency ปลอดภัย ต้อง Review ก่อน pin

**Who should care:** GitHub Actions, DevSecOps, Supply-chain Security, CI/CD; สำหรับ GitLab CI ไม่มีการรองรับ lockfile นี้โดยตรง

**Maturity:** Production Ready · **Recommendation:** Try · **Effort:** 20–45 นาที

**Sources:** https://github.blog/changelog/2026-10-28-github-actions-workflow-lockfiles-are-generally-available/ · https://github.com/github/gh-actions-lock

## 🧰 Tool of the Day — gh-actions-lock

**Problem:** Actions tags (เช่น actions/checkout@v4) เป็น references ที่ขยับได้ และ transitive actions อาจเปลี่ยนโดยไม่ตั้งใจ

**ลองบน Test Repository:**

~~~bash
gh extension install github/gh-actions-lock
gh actions-lock --no-fix
gh actions-lock
gh actions-lock --verify
~~~

คำสั่งแรกติดตั้ง CLI extension; --no-fix อ่านอย่างเดียว; คำสั่งไม่ใส่ flag จะสร้าง/แก้ lockfile จึงควร review diff ก่อน commit. การ verify ใช้ network และไม่ได้แทน vulnerability scanning.

**Maturity:** Production Ready · **Recommendation:** Try · **Effort:** 15–30 นาที

Source: https://github.com/github/gh-actions-lock

## 🧪 Try This Today

ทดลอง gh-actions-lock บน repository ที่มี GitHub Actions (รวมถึง Dev Engineer Radar) แบบไม่แตะ production: เริ่มจาก --no-fix เพื่อเห็นรายการ direct/transitive actions แล้วสร้าง actions.lock ใน branch ทดสอบ ตรวจ diff และใช้ --verify เป็น CI quality gate. สำหรับระบบหลักที่ใช้ GitLab CI ไม่ควรเข้าใจผิดว่าเครื่องมือนี้ใช้แทน GitLab dependency pinning ได้.
