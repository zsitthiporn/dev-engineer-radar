## 🔥 1. Top 5 — Must Know

### 🥇 NEW — GitHub Actions: pull_request_target จะถูก Block by Default (ประกาศ 2 พ.ย.)

GitHub เลื่อนวัน Enforcement จาก **2 พ.ย. เป็น 2 ธ.ค. 2026** สำหรับ Public Repositories โดยจะบล็อก `pull_request_target` เว้นแต่ Actions Event Policy อนุญาตโดยชัดแจ้ง มี Brownout **9 พ.ย. และ 16 พ.ย. เวลา 16:00–18:00 UTC** ก่อนบังคับจริง Private/Internal Repositories ไม่ได้รับผลกระทบ

**Why:** `pull_request_target` รันใน Base Repository Context และเข้าถึง Secrets ได้ การ Execute Untrusted Fork Code จึงเป็น Supply-chain Risk และ Workflow อาจหยุดทำงานเมื่อ Enforcement เริ่ม
**Who:** GitHub Actions, DevSecOps, Open Source Maintainers
**Maturity:** Production platform policy (evaluate mode ก่อน enforcement) · **Recommendation:** Try — audit workflows · **Effort:** 20–60 นาที
**Primary:** https://github.blog/changelog/2026-11-02-pull_request_target-blocked-by-default-december-2/

### 🥈 NEW — GitHub Security Assessments แสดง Repository Protection Status (2 พ.ย.)

GitHub Code Security และ Secret Risk Assessments แยก Findings ตาม Protected/Unprotected Repositories เพื่อช่วยจัดลำดับการเปิดใช้ Security Coverage ผ่าน Organization → Security → Assessments รองรับ GitHub Enterprise Cloud และ Team; Secret Risk Assessment บน GHES จะรองรับใน 3.24

**Why:** ช่วยหา Blind Spots ในการเปิดใช้ Secret/Code Protection โดยเฉพาะหลาย Repositories
**Who:** GitHub Organization Admins, AppSec, Platform Teams
**Maturity:** Production Ready บน Cloud · **Recommendation:** Try สำหรับองค์กรที่รองรับ · **Effort:** 15–30 นาที
**Primary:** https://github.blog/changelog/2026-11-02-security-risk-assessments-include-repository-protection-status/

### 🥉 NEW — Keycloak แชร์ Production OpenTelemetry Architecture Lessons (2 พ.ย.)

OpenTelemetry เผยแพร่ Case Study จาก Keycloak: การใช้ Generic Java Agent ทำให้ Startup ช้าลงหลายสิบวินาทีในสภาพแวดล้อมที่ทดสอบ จึงเลือก Native Quarkus Instrumentation; Metrics + Traces + Exemplars ช่วยวิเคราะห์ Authentication Latency และเน้น Threat Model ของ Push Telemetry

**Why:** เป็น Engineering Guidance ที่ใช้เทียบกับ .NET SDK vs eBPF/Auto-instrumentation ได้ แต่ **ไม่ใช่ Keycloak Release หรือผล Benchmark ของ .NET**
**Who:** SRE, Identity Platform, ASP.NET Core/OTel Engineers
**Maturity:** Production Ready architecture lessons · **Recommendation:** Try — benchmark native instrumentation · **Effort:** 1–2 ชั่วโมง
**Primary:** https://opentelemetry.io/blog/2026/devex-keycloak/
